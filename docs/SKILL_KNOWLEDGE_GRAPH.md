# DigitalMATSUMOTO ナレッジグラフ作成

渡されたテキストを、DigitalMATSUMOTO のグラフRAG が**LLM を使わずに直接取り込める**グラフ列の JSON に変換します。目標は「書いた事実が、あとで質問したときに検索で引けること」です。単に三つ組を並べるのではなく、検索の仕組み（後述）に合わせた形に設計してください。

## 1. 入力の受け取り方

| 入力 | 出力 |
|---|---|
| 文章だけ | その文章のグラフ列 JSON を1つ |
| 表 / CSV（`ID`・`テキスト` など） | 元の列はそのままに `ナレッジグラフ` 列を埋めた CSV。**ID の昇順**に並べる（Notion に列で貼るときのずれ防止） |

次の情報があれば使い、無ければ本文から推定して進めます（質問で止まらず、推定したことは最後のレポートに書く）。

- **主体**：その知識の持ち主（例: `駒木乃英人`）。表の `対象` 列があればそれ
- **既存のノード名と別名**（`dictionary.json` の `aliases`）：あれば必ずその表記に合わせる
- **既存の領域**（取材テーマ、家族、お酒 など）：あれば再利用する

## 2. 出力の書式

1行（1つの事実のまとまり）につき、次の JSON を**1行のコンパクトな形**で出します。

```json
{"triples":[{"subject":"主語","subject_type":"型","relation":"述語","object":"目的語","object_type":"型","props":{"キー":"値"}}],"node_props":[{"entity":"ノード","key":"属性名","value":"値"}]}
```

- `triples`：辺。`subject` / `relation` / `object` は**3つとも空にしない**
- `props`：辺の属性（時期・役割・評価など）。無ければ `{}`
- `node_props`：ノードの属性（生年月日・身長・肩書きなど）。`entity` と `key` は空にしない
- 使わない側（`triples` か `node_props`）は省略してよい。ただし**どちらか一方には必ず1件以上**入れる
- **Notion に貼る前提では、値の中の半角スペースを `\u0020` と書く**（例: `"バー\u0020Cielo"`）。貼り付け時にスペースが改行に化けて JSON が壊れ、その行が LLM 抽出に回ってしまうのを防ぐため。JSON のトークンの間には空白を入れない
- CSV で出すときは、セル内の `"` を `""` にして全体を `"` で囲む

## 3. 検索の仕組み（設計の前提）

1. **検索の起点は、質問文に含まれるノード名か別名の部分一致だけ**。`subject_type` / `object_type` は起点選びに使われない。→ 共通の因子（テーマ、ジャンル、媒体など）は**型ではなく実ノード**にする
2. **辿れるのは起点から2ホップ**（`HOPS: 2`）。**1ノードから辿る辺には上限**（`FANOUT_LIMIT`、多くの設定で 5〜40）がある。→ 主体に辺を集中させると大半が捨てられる
3. **手書きの行は LLM 抽出より優先**される。同じ属性が衝突したら手書きが勝つ

## 4. 設計ルール

### 4.1 ノードにするか、属性にするか

- **ノード**：ほかのものとも関係を持ちうるもの、質問の主題になりうるもの（人物・組織・場所・作品・出来事・テーマ・製品・活動）
- **属性**：数値・日付・肩書き・短い説明（身長、生年月日、役割、時期、評価）
- ❌ `{"subject":"駒木乃英人","relation":"身長","object":"176cm"}` → ✅ `node_props` に `{"entity":"駒木乃英人","key":"身長","value":"176cm"}`

### 4.2 「領域 → サブカテゴリ → 具体物」の3段にする

```text
主体 ─[関心を持つ]→ 領域 ←[属する]─ サブカテゴリ ←[分類される]─ 具体物 {<主体>の評価: …}
```

- 主体の**好みや関心**は、具体物へ直接張らずに領域経由にする。主体から直接出してよいのは、領域への `関心を持つ`、下の例外、本文に書かれた**行為そのもの**（`取材する` `執筆する` `習う` など）だけ。主体の辺は 30 前後までに収め、超えそうなら行為の辺を省いて props に任せる
- 好き嫌いや強弱は、述語を分けずに**辺の `props` の値**で表す。キーは `<主体>の評価`（例: `駒木乃の評価`）に統一し、値を `最も好き` / `特に好き` / `好き` / `まあまあ` / `好きではない` などにする
- 例外として、**「最も好む」と強い拒否（`忌避する` / `嫌悪する` / `絶縁する`）だけは主体から直接の辺も残す**（人格として一番効く情報のため）。その場合も分類の辺は別に書く
- 段は3つまで（2ホップで兄弟ノードに届く深さ）
- 構造の辺（`属する`・`関心を持つ`）は、**同じ領域に属する行すべてに重複して書く**。同じ辺は取り込み時に1本にまとまるので問題ない。むしろ行ごとに書いておくと、ある行を取り込みから外しても構造が崩れない
- 1つのサブカテゴリに具体物が集中しすぎたら（目安 15 超）、サブカテゴリを分ける

### 4.3 述語は少数に固定する

| 述語 | 使いどころ |
|---|---|
| `分類される` | 具体物 → サブカテゴリ（〜の一種） |
| `属する` | サブカテゴリ → 領域（〜の一部） |
| `関心を持つ` | 主体 → 領域 |
| `最も好む` / `忌避する` / `嫌悪する` / `絶縁する` | 主体 → 具体物（4.2 の例外） |
| 事実そのものの動詞 | `取材する` `寄稿する` `教える` `習う` `経営する` `所属する` `設立する` `居住する` `出身する` `著者` など |

- 「関連」「関係する」のような曖昧な述語は使わない
- 同じ意味の述語を増やさない（`好む` / `好き` / `選好する` / `支持する` を乱立させず、4.2 の評価 props にまとめる）
- 1つの表の中では、同じ種類の関係にいつも同じ述語を使う

### 4.4 型の語彙

`人物` `組織` `場所` `作品` `書籍` `出来事` `テーマ` `概念` `製品` `活動` `技能` `食品` `飲料` `キャラクター` `カテゴリ`（サブカテゴリ） `領域`（領域）。既存グラフに型があればそれに合わせる。

### 4.5 名前と別名

- ノード名は**ユーザーが質問で使う言葉**にする（「嗜好カテゴリ：映像」のような管理用の名前にしない）
- 固有名詞の表記は**原文のまま**。誤記らしきものがあっても勝手に直さず、レポートで指摘する
- 同じものの表記ゆれは1つの正式名にそろえ、ほかの表記は**別名としてレポートで提案**する（`dictionary.json` の `aliases` に入れる前提）
- **2文字以下の別名は提案しない**（部分一致で無関係な質問にも当たるため。例: 「母」は「母国」にも当たる）
- **自己ループを作らない**：主語と目的語が別名で同じノードになる辺は取り込み時に捨てられる。呼び名・略称は `node_props`（例: `{"entity":"駒木乃英人","key":"ペンネーム","value":"Eight"}`）か別名にする

### 4.6 書いてよい事実

- 本文に書かれている事実は、細かく分解して漏らさない（1文に複数の事実があれば複数の triple）
- 領域をまたぐ繋がり（家族の話と仕事の話が同じものに繋がる、など）は積極的に書く。グラフの深さはここから生まれる
- **一般常識の事実**（「ザアタリ難民キャンプはヨルダンにある」など）は、確実に正しいものだけ足してよい
- **主体本人についての事実は創作しない**。本文に無い経歴・好み・関係は書かない
- 否定の事実（「〜したことはない」）は、辺にせず `node_props` の値で書く

## 5. 手順

1. **全体を先に読む**：全行を通して、主体・登場する人物や組織・領域の候補を洗い出す。行ごとにばらばらに作ると同じものが別名で増えるため
2. **骨組みを決める**：領域とサブカテゴリの一覧を作る（既存があれば再利用）
3. **行ごとに分解する**：事実を triple / node_props にし、4.2 の構造の辺を足す
4. **セルフチェック**（6章）を通す
5. **出力**：JSON（または CSV）と、7章のレポート

## 6. セルフチェック（出力前に必ず）

- [ ] すべての JSON がパースできる（1行のコンパクト形式、トークン間に空白なし）
- [ ] すべての triple で `subject` / `relation` / `object` が空でない
- [ ] 各行に triple か node_prop が1件以上ある。テキストのある行は漏れなく埋まっている
- [ ] Notion 向けなら、値の中の半角スペースが `\u0020` になっている
- [ ] 主語と目的語が同じ（別名を含めて同じもの）の辺が無い
- [ ] 同じものが行によって別の表記になっていない
- [ ] 主体から直接出る辺は、領域への `関心を持つ`・4.2 の例外・本文に書かれた行為だけ（好みを直接張っていない）。その本数が 30 前後に収まっている
- [ ] 数値・日付だけのノードが無い
- [ ] 「関連」などの曖昧な述語、同義の述語の乱立が無い
- [ ] 本文に無い本人の事実を書いていない

## 7. 最後に添えるレポート

出力のあとに、短く次をまとめます。

1. **作った領域とサブカテゴリ**の一覧（どの具体物が入ったか、件数）
2. **`dictionary.json` に足すとよい別名**（そのまま貼れる JSON）
3. **推定したこと・判断に迷ったこと**（主体の推定、ノードか属性かの判断など）
4. **原文の誤記の疑い**（直さずに残したもの）
5. **主体の辺の数**の見込み

## 8. 例（同梱サンプル: 駒木乃英人）

### 例1：人物関係と属性

入力：「母が再婚し、姓が駒木乃になった。相手の駒木乃真吾は個人でバーをやっている人で、初対面のとき握手ではなく肩を叩いてきた。」（主体: 駒木乃英人、1994/11/3）

```json
{"triples":[{"subject":"駒木乃佳代","subject_type":"人物","relation":"再婚する","object":"駒木乃真吾","object_type":"人物","props":{"時期":"1994年11月"}},{"subject":"駒木乃真吾","subject_type":"人物","relation":"経営する","object":"バー\u0020Cielo","object_type":"組織","props":{}},{"subject":"駒木乃英人","subject_type":"人物","relation":"継子である","object":"駒木乃真吾","object_type":"人物","props":{}}],"node_props":[{"entity":"駒木乃英人","key":"姓の変遷","value":"佐野\u0020→\u0020駒木乃（1994年、母の再婚による）"},{"entity":"駒木乃真吾","key":"初対面の印象","value":"握手ではなく肩を叩いてきた"}]}
```

「バー Cielo」はほかの行とも繋がるのでノード、時期は辺の props、姓の変遷や印象は node_props にしています。

### 例2：3段の構造

入力（表）：

| ID | テキスト | 対象 |
|---|---|---|
| S-1 | ヨルダンのザアタリ難民キャンプで現地取材をした。 | 駒木乃英人 |
| S-2 | 記事「名前のない働き手たち」で、現場を支える人々を書いた。 | 駒木乃英人 |

出力：

```csv
ID,テキスト,対象,ナレッジグラフ
S-1,ヨルダンのザアタリ難民キャンプで現地取材をした。,駒木乃英人,"{""triples"":[{""subject"":""駒木乃英人"",""subject_type"":""人物"",""relation"":""取材する"",""object"":""ザアタリ難民キャンプ"",""object_type"":""場所"",""props"":{""形態"":""現地取材""}},{""subject"":""ザアタリ難民キャンプ"",""subject_type"":""場所"",""relation"":""分類される"",""object"":""移民・難民"",""object_type"":""カテゴリ"",""props"":{""駒木乃の関わり"":""現地取材""}},{""subject"":""移民・難民"",""subject_type"":""カテゴリ"",""relation"":""属する"",""object"":""取材テーマ"",""object_type"":""領域"",""props"":{}},{""subject"":""駒木乃英人"",""subject_type"":""人物"",""relation"":""関心を持つ"",""object"":""取材テーマ"",""object_type"":""領域"",""props"":{}},{""subject"":""ザアタリ難民キャンプ"",""subject_type"":""場所"",""relation"":""所在する"",""object"":""ヨルダン"",""object_type"":""場所"",""props"":{}}]}"
S-2,記事「名前のない働き手たち」で、現場を支える人々を書いた。,駒木乃英人,"{""triples"":[{""subject"":""駒木乃英人"",""subject_type"":""人物"",""relation"":""執筆する"",""object"":""名前のない働き手たち"",""object_type"":""作品"",""props"":{}},{""subject"":""名前のない働き手たち"",""subject_type"":""作品"",""relation"":""分類される"",""object"":""労働"",""object_type"":""カテゴリ"",""props"":{""駒木乃の関わり"":""記事""}},{""subject"":""労働"",""subject_type"":""カテゴリ"",""relation"":""属する"",""object"":""取材テーマ"",""object_type"":""領域"",""props"":{}},{""subject"":""駒木乃英人"",""subject_type"":""人物"",""relation"":""関心を持つ"",""object"":""取材テーマ"",""object_type"":""領域"",""props"":{}}],""node_props"":[{""entity"":""名前のない働き手たち"",""key"":""主題"",""value"":""現場を支える人々""}]}"
```

- 構造の辺（`移民・難民 → 取材テーマ`、`駒木乃英人 → 取材テーマ`）は各行に重複して書いている
- 「ヨルダン」は本文にある事実なので辺にした（本文に無ければ、確実な一般常識として足してよい）
- 「駒木乃英人 -[取材する]→ ザアタリ難民キャンプ」は本文の事実そのものなので主体から直接の辺として残している。具体物が増えて主体の辺が 30 を超えそうなら、この直接の辺は省き、`駒木乃の関わり` の props に任せる

### 例3：領域をまたぐ繋がり

入力：「四歳のとき、祖父エドゥアルド・アヤラに畳の上で足を八の字に描くステップ『オチョ』を教わった。ペンネームの Eight はここから来ている。」

```json
{"triples":[{"subject":"エドゥアルド・アヤラ","subject_type":"人物","relation":"教える","object":"オチョ","object_type":"技能","props":{"場所":"畳の上"}},{"subject":"駒木乃英人","subject_type":"人物","relation":"習う","object":"オチョ","object_type":"技能","props":{"年齢":"4歳"}},{"subject":"オチョ","subject_type":"技能","relation":"分類される","object":"タンゴのステップ","object_type":"カテゴリ","props":{}}],"node_props":[{"entity":"駒木乃英人","key":"ペンネーム","value":"Eight"},{"entity":"駒木乃英人","key":"ペンネームの由来","value":"祖父に教わった8の字のステップ「オチョ」"}]}
```

家族（祖父）と仕事（ペンネーム）が「オチョ」で繋がるので、どちらから聞いても2ホップで届きます。「Eight」は主体の別名なので辺にせず node_props にし、レポートで別名（`"Eight": "駒木乃英人"`）として提案します。

レポート例（抜粋）：

```json
{"aliases": {"Eight": "駒木乃英人", "祖父アヤラ": "エドゥアルド・アヤラ", "8の字のステップ": "オチョ"}}
```
