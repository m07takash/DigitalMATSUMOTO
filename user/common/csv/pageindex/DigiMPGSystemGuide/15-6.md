WebUI と同じ状態 (`status.yaml`) を API 経由で参照・変更できます。詳細な機能説明は [セッションサマリー](#セッションサマリーユーザー定義のセッション状態文書) を参照。

**GET `/sessions/{session_id}/summary` — 現在の状態を取得**

```bash
curl -s http://localhost:8899/sessions/API20260702_XXX/summary
```

レスポンス:
```json
{
  "session_id": "API20260702_XXX",
  "enabled":    true,
  "template":   "## 顧客\n- 会社名:\n- 担当者:\n\n## 課題\n-",
  "content":    "## 顧客\n- 会社名: ABC商事\n- 担当者: 田中さん\n\n## 課題\n- 業務効率化",
  "updated_at": "2026-07-02 14:32:11"
}
```

- `enabled` — 有効/無効
- `template` — 現在保存されているテンプレート
- `content` — LLM が対話ごとに更新した最新のサマリー本文
- `updated_at` — content の最終更新時刻

**POST `/sessions/{session_id}/summary` — 設定を変更**

`enabled` / `template` それぞれ `Optional`。片方だけ送れば他方は保持されます。

```bash
# プリセットの「顧客ヒアリング」テンプレートを適用し、機能を有効化
curl -X POST http://localhost:8899/sessions/API20260702_XXX/summary \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "template": "## 顧客情報\n- 会社名:\n- 担当者:\n\n## 課題\n-\n\n## 次のアクション\n-"
  }'

# 途中で一時的に無効化（template は保持）
curl -X POST http://localhost:8899/sessions/API20260702_XXX/summary \
  -H "Content-Type: application/json" \
  -d '{"enabled": false}'
```

> `content` はここでは変更できません（バックグラウンドの自動更新が所有）。テンプレートを変えれば次のターン以降で LLM が新テンプレートに沿って本文を再生成します。

**GET `/session_summary_presets` — プリセット一覧**

```bash
curl -s http://localhost:8899/session_summary_presets
```

レスポンス:
```json
{
  "presets": [
    {"name": "None",       "description": "空のテンプレート...",  "template": ""},
    {"name": "顧客ヒアリング", "description": "顧客ヒアリング用...", "template": "## 顧客情報\n- ..."},
    {"name": "課題整理",    "description": "問題解決系...",       "template": "## 現状\n- ..."},
    {"name": "進捗管理",    "description": "プロジェクト...",     "template": "..."},
    {"name": "タスク管理",  "description": "TODO 抽出用...",     "template": "..."},
    {"name": "会議メモ",    "description": "会議録形式...",       "template": "..."},
    {"name": "研究ログ",    "description": "研究 / 調査系...",   "template": "..."}
  ]
}
```

プリセットの追加・編集は [`user/common/mst/session_summary_presets.json`](user/common/mst/session_summary_presets.json) を編集するだけです（サーバ再起動不要、次回 API 呼び出し時に反映）。

**インライン指定（`/run` 経由でワンショット有効化）**

`/run` の payload に `session_summary_enabled` / `session_summary_template` を含めれば、その同じターンから機能が有効化されます。stateless クライアント（LINE bot 等）向け:

```bash
curl -X POST http://localhost:8899/run \
  -H "Content-Type: application/json" \
  -d '{
    "service_info": {"SERVICE_ID": "DEMO"},
    "user_info":    {"USER_ID": "DemoUser"},
    "user_input":   "ABC商事の田中さんと打ち合わせ。金額は100万円。",
    "agent_file":   "agent_10Sample.json",
    "session_summary_enabled": true,
    "session_summary_template": "## 顧客\n- 会社名:\n- 担当者:\n\n## 金額\n-"
  }'
```

初回リクエストで `status.yaml` に保存され、以降のターンでは自動注入 + 自動更新が働きます。
