会話履歴の保存バックエンドは `setting.yaml` の `SESSION_STORE_METHOD` で切り替えます。デフォルトは **JSON**（従来の 1 セッション 1 ファイル `chat_memory.json`）。長対話（数百ターン超）でファイル書き換えのコストが目立つケースや、複数プロセスから同一セッションに書き込む用途では **PostgreSQL** / **CosmosDB** を推奨します。

| モード | 保存形態 | 特徴 |
|---|---|---|
| **JSON**（既定） | 1 ターン確定ごとに `user/<prefix><session_id>/chat_memory.json` を丸ごと書き直し | 追加依存なし。小〜中規模セッション向け。長いセッションで読み書きが線形に遅くなる |
| **PostgreSQL** | `digim_chat_history` テーブルに 1 ターン 1 行（JSONB payload） | ターン単位 UPSERT で長対話でも一定速度。APE 分析用の `digim_dialogs` とは別テーブル |
| **CosmosDB** | SQL API コンテナに 1 ターン 1 ドキュメント（partition key `/session_id`） | Azure 上の企業チャットボットで一般的な形。標準の 400 RU/s で開始可 |

**共通ルール**:
- `SESSION_STORE_METHOD` を切り替えても既存セッションは壊れない。ディスク上に `chat_memory.json` が残っているセッションは、以降の読み書きも JSON パス経由で行われる（**ハイブリッド共存**）
- 新規セッションだけが設定したバックエンドに乗る
- サイドファイル（`status.yaml` / `vec/*.npy` / `contents/` / `analytics/`）は設定に関係なくディスク側に置かれる

#### PostgreSQL バックエンドのセットアップ

**1. `system.env` に接続情報**

```env
POSTGRES_HOST=your-host.example.com
POSTGRES_PORT=5432
POSTGRES_DB=digimatsu
POSTGRES_USER=digim_app
POSTGRES_PASSWORD=***
# SSL モード（Azure Postgres では require が必須）
POSTGRES_SSLMODE=require
```

**2. `setting.yaml` を切替**

```yaml
SESSION_STORE_METHOD: "PostgreSQL"
```

**3. テーブル作成**（初回書き込み時に自動作成もされます。DBA が事前プロビジョンする場合は以下）

```sql
-- 会話履歴のライブ R/W テーブル。1 行 = (seq, sub_seq) 単位。sub_seq=0 は SETTING、sub_seq>=1 が対話ターン
CREATE TABLE IF NOT EXISTS digim_chat_history (
    session_id  TEXT      NOT NULL,
    seq         INTEGER   NOT NULL,
    sub_seq     INTEGER   NOT NULL,
    data        JSONB     NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (session_id, seq, sub_seq)
);
CREATE INDEX IF NOT EXISTS idx_digim_chat_history_session
    ON digim_chat_history (session_id);
CREATE INDEX IF NOT EXISTS idx_digim_chat_history_session_seq
    ON digim_chat_history (session_id, seq DESC);
```

**APE のミラーテーブル（`digim_sessions` / `digim_dialogs` / `digim_references`）とは別物** なので混同しないこと。あちらは分析用エクスポート、こちらはランタイムの R/W。

依存: `psycopg2-binary`（`requirements.txt` に既存）。

#### CosmosDB バックエンドのセットアップ

**1. `system.env` に接続情報**

```env
COSMOS_ENDPOINT=https://your-account.documents.azure.com:443/
COSMOS_KEY=***
```

**2. `setting.yaml` を切替**

```yaml
SESSION_STORE_METHOD: "CosmosDB"
COSMOS_DATABASE: "digimatsu"
COSMOS_CONTAINER: "chat_history"
```

**3. Database + Container 作成（Azure Portal / CLI）**

```bash
az cosmosdb sql database create \
    --account-name <cosmos-account> --resource-group <rg> \
    --name digimatsu

az cosmosdb sql container create \
    --account-name <cosmos-account> --resource-group <rg> \
    --database-name digimatsu --name chat_history \
    --partition-key-path "/session_id" --throughput 400
```

依存: `azure-cosmos`（optional。未インストールでも起動は可能で、`CosmosDB` モード選択時のみ必要）:

```bash
pip install azure-cosmos
```

`CosmosDB` を指定していてこの依存が無い場合は、警告ログを出して JSON ストアにフォールバック。

#### モード切替時の注意

- **既存 JSON セッション**: ディスク上に `chat_memory.json` があれば従来通り読み書きされる（何もしなくて良い）
- **PG/Cosmos → JSON の逆戻り**: 設定を JSON に戻すと、PG/Cosmos 側に残った履歴は JSON モードから見えなくなる（データは削除されないが不可視）。移行する場合は事前にエクスポートを
- **一括マイグレーション CLI は未提供**: 「既存 JSON セッションを PG に移す」バッチは現状ありません。必要になったら書けば良く、ハイブリッド共存で運用上は困りません
