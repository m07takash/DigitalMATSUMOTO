**メモリダイジェストとは別**の、**ユーザーが書式を指定できるセッション状態文書**。対話のたびに軽量LLM (デフォルトは `agent_65SessionSummary.json` → Gemini-3.5-Flash) がバックグラウンドでテンプレートを埋めていき、次以降のプロンプトに `[Current Session Summary]` ブロックとして注入されます。

**用途例**:
- **顧客ヒアリング**: 「会社名 / 担当者 / 課題 / 次アクション」を毎ターン蓄積 → 数ターン後に会社の全体像を Agent が保持している状態を作る
- **課題整理**: 「現状 / 原因 / 解決策 / 制約」を対話の中で埋めていく
- **タスク管理**: 「高優先 / 中優先 / 低優先 / 完了」を明示的な TODO リストとして保持

**Chat 画面の「Session Summary Setting」で設定** (画面上部の Chat Name から User Memory expander の直下に配置):

- ☑ **Enable session summary** — 対話ごとに自動更新 + 次プロンプトへの注入を有効化 (デフォルト OFF)
- **Preset** — [`user/common/mst/session_summary_presets.json`](user/common/mst/session_summary_presets.json) からテンプレートを選択して展開:
  - 顧客ヒアリング / 課題整理 / 進捗管理 / タスク管理 / 会議メモ / 研究ログ / None (自由編集)
- **Template (Markdown)** — 選択したプリセットを元に自由編集 (見出し `## ...` は LLM 更新後も維持されます)
- **Save summary settings** で `status.yaml` に永続化

> UI ラベルとログは英語で統一しています (`Session Summary Setting` / `Enable session summary` / `Preset` / `Template (Markdown)` / `Save summary settings` / `Latest summary (updated: ...)` / `Active template` など)。

**Detail Information → Session Summary タブ** で最新のサマリー本文が確認できます。プロンプトに注入された内容 (LLM が受け取ったブロック) は「LLM Input」タブの **Session Summary (context block)** で確認できます。

**メモリダイジェストとの並列実行**:

Session Summary の更新と Memory Digest の生成は**別スレッドで完全並列**に走ります (両方とも `threading.Thread(daemon=True).start()` で非同期起動)。どちらもチャット応答の返却をブロックしません。両方が同時に `status.yaml` を書き込む場合、[`DigiM_Util.save_yaml_file`](DigiM_Util.py) の per-file lock (`_yaml_file_locks`) で保護されるため、フィールドの取りこぼしは発生しません。

**軽量エージェントによる更新**:

デフォルトでは `agent_65SessionSummary.json` (Gemini-3.5-Flash デフォルト) がグローバルフォールバックとして使われるため、**全 Chat エージェントで追加設定不要**で軽量モデルによるサマリー更新が有効になります。特定のエージェントで別モデルを使いたい場合は、そのエージェント JSON の `SUPPORT_AGENT` に:

```json
"SUPPORT_AGENT": {
    ...
    "SESSION_SUMMARY": "agent_65SessionSummary.json"
}
```

を追加 (既に `agent_01DigitalMATSUMOTO.json` と `agent_10Sample.json` は設定済み)。エージェント側で `DEFAULT` エンジンを `GPT-5.4-nano` や `Claude-Haiku-4.5` に変えれば、全体を切り替えることもできます。

**プロンプトへの注入位置**:

`session_summary_enabled=True` かつ `session_summary_content` に本文がある場合、[`DigiMatsuExecute_Practice`](DigiM_Execute.py) は以下の順でクエリを組み立てます:

```
[Current Session Summary]
(Confirmed facts about this session so far. Prefer these values ...)

{session_summary_content}
---

{user_memory_context}
{knowledge_context}
{prompt_template}
{user_query}
{situation_prompt}
```

Summary が最上位に来るのは、「セッション内で確定した情報」がその他の generic な memory / RAG より優先されるべきという設計判断です。
